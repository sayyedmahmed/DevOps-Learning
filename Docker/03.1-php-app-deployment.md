# PHP App Deployment (Native + Docker)

Complete reference to recreate the environment, understand what broke, and know which command does what. Beginner friendly.

## 1. What we build

Two separate setups on the same VM:

| Setup | Port | Serves |
|---|---|---|
| Native (host Nginx) | 80 | `/usr/share/nginx/html` |
| Docker (container) | 8080 | `/var/www/html` inside the container |

Both can run at the same time. Native on 80, container on 8080.

## 2. Architecture

```
Native:     Browser -> Nginx (host, port 80) -> PHP-FPM (socket) -> index.php
Container:  Browser -> Docker (port 8080 -> container 80) -> Nginx -> PHP-FPM (127.0.0.1:9000) -> index.php
```

Both work the same way. Nginx forwards `.php` requests to PHP-FPM, gets HTML back, returns it to the browser.

## 1.3 Deploy to web root

```bash
sudo cp -r ~/php-app/src/* /usr/share/nginx/html/
sudo chown -R apache:apache /usr/share/nginx/html
```

- `cp -r` copies files and folders recursively.
- `chown -R` sets owner recursively. Nginx and PHP-FPM both run as `apache` on AlmaLinux.

## 1.4 Create site config

```bash
sudo vim /etc/nginx/conf.d/php-app.conf
```

```nginx
server {
    listen 80 default_server;
    server_name _;
    root /usr/share/nginx/html;
    index index.php index.html;

    location / {
        try_files $uri $uri/ /index.php;
    }

    location ~ \.php$ {
        try_files $uri =404;
        fastcgi_pass unix:/run/php-fpm/www.sock;
        fastcgi_index index.php;
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    }
}
```

- `listen 80 default_server`: accept port 80 as the default site.
- `root`: where files live.
- `location ~ \.php$`: match PHP requests, send to PHP-FPM.
- `fastcgi_pass`: the socket PHP-FPM listens on. Must match `listen` in `/etc/php-fpm.d/www.conf` (default is `/run/php-fpm/www.sock`).

## 1.5 Remove default server block from `nginx.conf`

```bash
sudo vim /etc/nginx/nginx.conf
```

Find the block starting with `server {`. Delete it entirely (Vim: cursor on `server {`, press `V`, arrow to closing `}`, press `d`).

Why: AlmaLinux ships a default `server { }` block that also listens on port 80. Two blocks on port 80 fight each other. Your `php-app.conf` should be the only one.

Keep the `http { }` section and this line inside it:

```nginx
include /etc/nginx/conf.d/*.conf;
```

## 1.6 SELinux and firewall

```bash
sudo setsebool -P httpd_can_network_connect 1
sudo restorecon -Rv /usr/share/nginx/html
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --reload
```

- `setsebool`: allows Nginx to connect to the PHP-FPM socket. `-P` makes it persist.
- `restorecon`: resets file security labels to defaults.
- `firewall-cmd`: opens port 80.

Without these, requests fail with `502` or connection refused.

## 1.7 Start and test

```bash
sudo systemctl enable --now nginx php-fpm
sudo nginx -t
sudo systemctl reload nginx
sudo systemctl restart php-fpm
curl -I http://localhost/
```

- `systemctl enable --now`: starts now and on every boot.
- `nginx -t`: checks config syntax. Always run after edits.
- `reload`: applies config without dropping connections.
- `restart`: full stop and start.
- `curl -I`: fetches headers only.

Expected:

```
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
```

Browser: `http://<vm-ip>/` shows the app.

### `Dockerfile`

```dockerfile
FROM almalinux:9

RUN dnf install -y epel-release && \
    dnf install -y nginx php php-fpm php-cli supervisor && \
    dnf clean all

WORKDIR /var/www/html

COPY src/ /var/www/html/
COPY nginx.conf /etc/nginx/nginx.conf
COPY supervisord.conf /etc/supervisord.conf

RUN sed -i 's/^user = .*/user = nginx/' /etc/php-fpm.d/www.conf && \
    sed -i 's/^group = .*/group = nginx/' /etc/php-fpm.d/www.conf && \
    sed -i 's|^listen = .*|listen = 127.0.0.1:9000|' /etc/php-fpm.d/www.conf && \
    chown -R nginx:nginx /var/www/html

RUN mkdir -p /run/php-fpm && chown nginx:nginx /run/php-fpm

EXPOSE 80
CMD ["/usr/bin/supervisord", "-c", "/etc/supervisord.conf"]
```

Line by line:
- `FROM almalinux:9`: base image, same OS as the host.
- `RUN dnf install`: installs Nginx, PHP, PHP-FPM, Supervisor.
- `WORKDIR`: web root inside the image.
- `COPY src/`: app files.
- `COPY nginx.conf`: replaces the default Nginx config.
- `COPY supervisord.conf`: brings in Supervisor config.
- `RUN sed`: sets PHP-FPM user to `nginx`, listen to `127.0.0.1:9000`, fixes file ownership.
- `RUN mkdir -p /run/php-fpm`: **required**. Container has no systemd, so this directory must be created manually or PHP-FPM crashes.
- `CMD`: Supervisor becomes PID 1 and starts both services.

### `nginx.conf`

```nginx
user nginx;
worker_processes auto;
error_log /var/log/nginx/error.log notice;
pid /run/nginx.pid;

include /usr/share/nginx/modules/*.conf;

events { worker_connections 1024; }

http {
    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" "$http_x_forwarded_for"';
    access_log /var/log/nginx/access.log main;
    sendfile on;
    tcp_nopush on;
    keepalive_timeout 65;
    types_hash_max_size 4096;
    include /etc/nginx/mime.types;
    default_type application/octet-stream;

    server {
        listen 80 default_server;
        server_name _;
        root /var/www/html;
        index index.php index.html;

        location / { try_files $uri $uri/ /index.php; }

        location ~ \.php$ {
            try_files $uri =404;
            fastcgi_pass 127.0.0.1:9000;
            fastcgi_index index.php;
            include fastcgi_params;
            fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        }
    }
}
```

Key differences from native:
- `user nginx`: container-specific user.
- Server block is inline in `http { }`, no `conf.d/` split.
- `fastcgi_pass 127.0.0.1:9000` (TCP) instead of a unix socket.
- `listen 80 default_server`: **must be 80**, not 8080. See Issue 4.

### `supervisord.conf`

```ini
[supervisord]
nodaemon=true
logfile=/var/log/supervisord.log
pidfile=/var/run/supervisord.pid

[program:php-fpm]
command=/usr/sbin/php-fpm -F
autostart=true
autorestart=true
stdout_logfile=/dev/stdout
stdout_logfile_maxbytes=0
stderr_logfile=/dev/stderr
stderr_logfile_maxbytes=0

[program:nginx]
command=/usr/sbin/nginx -g "daemon off;"
autostart=true
autorestart=true
stdout_logfile=/dev/stdout
stdout_logfile_maxbytes=0
stderr_logfile=/dev/stderr
stderr_logfile_maxbytes=0
```

Why Supervisor: Docker runs one main process. Your app needs two (Nginx + PHP-FPM). Supervisor is the one process, and it starts and monitors both.

- `nodaemon=true`: Supervisor stays in foreground, keeps the container alive.
- `[program:php-fpm]` and `[program:nginx]`: one per service.
- `-F` and `daemon off`: keep each service in foreground so Supervisor can track it.
- `autorestart=true`: restart if crashed.
- `stdout_logfile=/dev/stdout`: forwards logs to `docker logs`.

# Part 3: Issues we hit and how we fixed them

## Issue 1: Native app showed default Nginx welcome page

**Symptom:** Browser on port 80 showed "Welcome to nginx", not the PHP app.

**Cause:** Two `server { }` blocks both listened on port 80. One was in `/etc/nginx/nginx.conf` (the shipped default), the other in `conf.d/php-app.conf`. Nginx kept the first and ignored the second.

**Fix:** Deleted the `server { }` block from `nginx.conf`. Only `conf.d/php-app.conf` remains.

**Identify:**

```bash
sudo nginx -T | grep -nE "^# configuration file|listen 80"
```

Shows every file that owns a port 80 block.

## Issue 2: `conflicting server name "_" on 0.0.0.0:80, ignored`

**Symptom:** `nginx -t` printed the warning above.

**Cause:** Both `default.conf` (welcome page) and `php-app.conf` were on port 80 with `server_name _`.

**Fix:** Moved `default.conf` to port 8080, made `php-app.conf` the `default_server` on 80. Then removed `default.conf` entirely since it was not needed.

## Issue 3: Docker daemon would not start

**Symptom:** `systemctl start docker` failed. `journalctl` showed:

```
failed to start daemon: Error initializing network controller: ...
Warning: Extension addrtype revision 0 not supported, missing kernel module?
```

**Cause:** Kernel module `xt_addrtype` was not loaded. Docker needs it for iptables NAT rules.

**Fix:**

```bash
sudo modprobe xt_addrtype
sudo modprobe br_netfilter
sudo modprobe ip_tables
sudo modprobe iptable_nat
echo -e 'xt_addrtype\nbr_netfilter\nip_tables\niptable_nat' | sudo tee /etc/modules-load.d/docker.conf
sudo systemctl reset-failed docker.service docker.socket
sudo systemctl start docker
```

`modprobe` loads a kernel module now. `/etc/modules-load.d/*.conf` loads it on every boot. `reset-failed` clears the retry-limit state so systemd will try again.

## Issue 4: PHP-FPM crashed in the container

**Symptom:** `docker logs` showed repeating:

```
ERROR: Unable to create the PID file (/run/php-fpm/php-fpm.pid).: No such file or directory
ERROR: FPM initialization failed
```

**Cause:** The directory `/run/php-fpm/` does not exist in the container. On a normal host, systemd creates it. In a container there is no systemd.

**Fix:** Added this line to `Dockerfile` before `EXPOSE 80`:

```dockerfile
RUN mkdir -p /run/php-fpm && chown nginx:nginx /run/php-fpm
```

Rebuild with `docker build --no-cache -t php-app-image .` to make sure the new line runs.

## Issue 5: Corrupted `listen` line in `nginx.conf`

**Symptom:** Nginx inside the container crashed with:

```
nginx: [emerg] host not found in "8080808080808080..." of the "listen" directive
```

**Cause:** A paste error or stuck key produced a long string of `8080` in the `listen` directive.

**Fix:** Rewrote the file cleanly:

```bash
cat > ~/php-docker/nginx.conf <<'EOF'
... full content ...
EOF
```

`cat > file <<'EOF'` overwrites the file with the content between the markers. Safer than fixing a corrupted line with vim.

## Issue 6: `Connection reset by peer` on port 8080

**Symptom:** `curl -I http://localhost:8080/` returned:

```
curl: (56) Recv failure: Connection reset by peer
```

**Cause:** Nginx inside the container was listening on **8080**, but `docker run -p 8080:80` maps host 8080 to **container 80**. Traffic reached container port 80, where nothing was listening.

**Identify:**

```bash
docker ps
# shows: 0.0.0.0:8080->80/tcp
docker exec php-app-container grep listen /etc/nginx/nginx.conf
# shows: listen 8080 default_server;   <- mismatch!
```

The mapping sends traffic to container port 80, but Nginx is on container port 8080.

**Fix:** Changed `nginx.conf` to:

```nginx
listen 80 default_server;
```

Rebuilt with `--no-cache`, reran. `curl -I http://localhost:8080/` returned `200 OK`.

**Rule to remember:**

In `docker run -p X:Y`:
- `X` is host port (what you visit)
- `Y` is container port (what the app listens on)
- `nginx.conf`'s `listen` must equal `Y`, not `X`

# Part 4: Start and stop

## Native services

```bash
# Start
sudo systemctl start nginx
sudo systemctl start php-fpm

# Stop
sudo systemctl stop nginx
sudo systemctl stop php-fpm

# Restart after config change
sudo systemctl reload nginx
sudo systemctl restart php-fpm

# Status
sudo systemctl status nginx php-fpm --no-pager

# Auto-start at boot
sudo systemctl enable nginx php-fpm
sudo systemctl disable nginx php-fpm
```

## Docker container

```bash
# Start existing container
docker start php-app-container

# Stop
docker stop php-app-container

# Restart
docker restart php-app-container

# Status
docker ps
docker ps -a

# Logs
docker logs php-app-container
docker logs -f php-app-container

# Shell inside
docker exec -it php-app-container sh

# Rebuild after editing src/ or configs
docker rm -f php-app-container
docker build -t php-app-image .
docker run -d --name php-app-container -p 8080:80 php-app-image

# Remove everything
docker rm -f php-app-container
docker rmi php-app-image
```
