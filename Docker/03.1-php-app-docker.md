# Docker PHP Application Deployment

Single container running Nginx, PHP-FPM, and the PHP application. No Docker Compose. Based on the native AlmaLinux setup, containerized.

## 1. Architecture

```
Browser  ->  Docker (port 80)  ->  Supervisor (PID 1)
                                     ├── Nginx  (port 80)
                                     └── PHP-FPM (127.0.0.1:9000)

Request flow:
Browser -> Nginx -> PHP-FPM -> index.php -> HTML back to browser
```

Two services in one container. Supervisor starts and monitors both. One port exposed.

## 2. Why Supervisor is required

Docker containers run **one main process**. The `CMD` line in the Dockerfile is that process. When it exits, the container stops.

The PHP application needs **two** processes at the same time:

- Nginx (answers HTTP on port 80)
- PHP-FPM (executes PHP on port 9000)

The `CMD` line accepts only one command. If you pick one, the other never runs and the application breaks:

| `CMD` you try | Result |
|---|---|
| `CMD ["nginx", "-g", "daemon off;"]` | Nginx runs. PHP-FPM never starts. Browser shows `502 Bad Gateway` |
| `CMD ["php-fpm", "-F"]` | PHP-FPM runs. Nginx never starts. Browser shows connection refused |
| `CMD ["sh", "-c", "nginx & php-fpm -F"]` | Both start. Logs are lost. No auto restart on crash. Fragile |

Supervisor solves this. It becomes PID 1, starts both services as child processes, restarts them if they crash, and forwards their logs to `docker logs`. That is all it does.

## 3. When Supervisor can be skipped

Use a single-process image that bundles PHP inside a web server:

```dockerfile
FROM php:8.2-apache
COPY src/ /var/www/html/
```

Apache runs PHP through `mod_php`. No separate PHP-FPM, no Nginx, no Supervisor. One process, one container.

**Tradeoff:** you lose Nginx, you lose the FastCGI architecture, and the setup no longer matches what you built natively.

**Decision:**

- Keep Nginx + PHP-FPM → use Supervisor (this document)
- Simplest possible container → use `php:apache`, skip this document

## 4. Project layout

```
php-docker/
├── Dockerfile
├── nginx.conf
├── supervisord.conf
└── src/
    ├── index.php
    └── style.css
```

| File | Purpose |
|---|---|
| `Dockerfile` | Build recipe. Base image, packages, files, startup command |
| `nginx.conf` | Nginx configuration inside the image. Replaces the default |
| `supervisord.conf` | Starts and monitors Nginx and PHP-FPM together |
| `src/` | Application files. Unchanged from the native setup |

## 5. Single nginx.conf vs conf.d

Native setup used two files:

```
/etc/nginx/nginx.conf
/etc/nginx/conf.d/php-app.conf
```

Container uses one file:

```
/etc/nginx/nginx.conf   (everything inside)
```

Functionally identical. The native `nginx.conf` had this line:

```nginx
include /etc/nginx/conf.d/*.conf;
```

That line pastes every file in `conf.d/` into `nginx.conf` at startup. Nginx treats the result as one merged config. The container writes the `server { }` block directly inside `http { }` and skips the extra file.

| Use one file | Use conf.d |
|---|---|
| Single application | Multiple sites in one image |
| Simpler COPY | Easier to add sites later |
| No default block to remove | Shared config across images |

For one application, one file is cleaner.

## 6. File contents

### `Dockerfile`

```dockerfile
FROM almalinux:9

RUN dnf install -y epel-release && \
    dnf install -y nginx php php-fpm php-cli supervisor && \
    dnf clean all

WORKDIR /var/www/html

COPY src/ /var/www/html/
COPY nginx.conf /etc/nginx/nginx.conf
COPY supervisord.conf /etc/supervisord.conf

RUN sed -i 's/^user = .*/user = nginx/' /etc/php-fpm.d/www.conf && \
    sed -i 's/^group = .*/group = nginx/' /etc/php-fpm.d/www.conf && \
    sed -i 's|^listen = .*|listen = 127.0.0.1:9000|' /etc/php-fpm.d/www.conf && \
    chown -R nginx:nginx /var/www/html

EXPOSE 80

CMD ["/usr/bin/supervisord", "-c", "/etc/supervisord.conf"]
```

Line by line:

- `FROM almalinux:9` matches the native host OS.
- `RUN dnf install` installs the four required packages.
- `WORKDIR` sets the web root.
- `COPY src/` brings the application files.
- `COPY nginx.conf` replaces the default config. This is why no welcome page appears.
- `COPY supervisord.conf` brings the Supervisor config.
- `RUN sed` sets PHP-FPM user to `nginx` and listen address to `127.0.0.1:9000`. Same intent as editing `www.conf` natively.
- `chown` sets ownership to the user Nginx and PHP-FPM run as.
- `EXPOSE 80` documents the port. Actual mapping happens at `docker run`.
- `CMD` starts Supervisor as PID 1.

### `nginx.conf`

```nginx
user nginx;
worker_processes auto;
error_log /var/log/nginx/error.log notice;
pid /run/nginx.pid;

include /usr/share/nginx/modules/*.conf;

events {
    worker_connections 1024;
}

http {
    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" "$http_x_forwarded_for"';

    access_log /var/log/nginx/access.log main;

    sendfile on;
    tcp_nopush on;
    keepalive_timeout 65;
    types_hash_max_size 4096;

    include /etc/nginx/mime.types;
    default_type application/octet-stream;

    server {
        listen 80 default_server;
        server_name _;
        root /var/www/html;
        index index.php index.html;

        location / {
            try_files $uri $uri/ /index.php;
        }

        location ~ \.php$ {
            try_files $uri =404;
            fastcgi_pass 127.0.0.1:9000;
            fastcgi_index index.php;
            include fastcgi_params;
            fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        }
    }
}
```

Differences from the native site config:

- `user nginx;` instead of `user apache;`.
- `server { }` written inline inside `http { }` instead of a separate file.
- `fastcgi_pass 127.0.0.1:9000` instead of a unix socket. Simpler inside a container.
- `root /var/www/html` matches the `WORKDIR` in the Dockerfile.

Everything else (`try_files`, `SCRIPT_FILENAME`, `index` order) is identical to the native `php-app.conf`.

### `supervisord.conf`

```ini
[supervisord]
nodaemon=true
logfile=/var/log/supervisord.log
pidfile=/var/run/supervisord.pid

[program:php-fpm]
command=/usr/sbin/php-fpm -F
autostart=true
autorestart=true
stdout_logfile=/dev/stdout
stdout_logfile_maxbytes=0
stderr_logfile=/dev/stderr
stderr_logfile_maxbytes=0

[program:nginx]
command=/usr/sbin/nginx -g "daemon off;"
autostart=true
autorestart=true
stdout_logfile=/dev/stdout
stdout_logfile_maxbytes=0
stderr_logfile=/dev/stderr
stderr_logfile_maxbytes=0
```

- `nodaemon=true` keeps Supervisor in the foreground, which keeps the container alive.
- `[program:php-fpm]` starts PHP-FPM in foreground with `-F`.
- `[program:nginx]` starts Nginx with `daemon off` so it stays in foreground.
- `autostart=true` starts each service when the container starts.
- `autorestart=true` restarts a service if it crashes.
- `stdout_logfile=/dev/stdout` forwards logs to the container output so `docker logs` works.

## 7. Deployment steps

### Step 1: Verify Docker

```bash
docker --version
docker ps
```

If `docker ps` fails with permission denied:

```bash
sudo usermod -aG docker $USER
```

Log out and back in for the change to apply.

### Step 2: Create the project folder

```bash
mkdir -p ~/php-docker/src
cd ~/php-docker
```

`mkdir -p` creates the folder and any missing parents.

### Step 3: Create the five files

```bash
cd ~/php-docker/src
vim index.php
vim style.css

cd ~/php-docker
vim Dockerfile
vim nginx.conf
vim supervisord.conf
```

Vim basics: `i` to insert, `Esc` to leave insert, `:wq` to save and quit.

### Step 4: Verify structure

```bash
ls -l ~/php-docker/
ls -l ~/php-docker/src/
```

Expected:

```
~/php-docker/
├── Dockerfile
├── nginx.conf
├── supervisord.conf
└── src/
    ├── index.php
    └── style.css
```

### Step 5: Free port 80 on the host

```bash
sudo systemctl stop nginx
sudo systemctl disable nginx
sudo ss -ltnp | grep :80
```

Empty output means port 80 is free. If host Nginx must stay running, use `-p 8080:80` at `docker run` time and visit `http://<vm-ip>:8080/`.

### Step 6: Build the image

```bash
cd ~/php-docker
docker build -t php-app .
```

- `docker build` reads the `Dockerfile` in the current directory.
- `-t php-app` tags the image.
- `.` is the build context.

First build takes 1 to 3 minutes. Later builds reuse cached layers.

Common build errors:

| Error | Cause |
|---|---|
| `almalinux:9 not found` | Network issue pulling the base image |
| `COPY failed` | A file is missing from the project folder |
| `dnf install` timeout | Repository unreachable |

### Step 7: Run the container

```bash
docker run -d --name php-app -p 80:80 php-app
```

- `-d` runs in background.
- `--name php-app` sets the container name.
- `-p 80:80` maps host port 80 to container port 80.

### Step 8: Verify

```bash
docker ps
docker logs php-app
curl -I http://localhost/
```

Expected from `curl -I`:

```
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
```

Open `http://<vm-ip>/` in a browser. The purple card appears.

### Step 9: Update application files

Two options.

**Rebuild after every change:**

```bash
docker rm -f php-app
docker build -t php-app .
docker run -d --name php-app -p 80:80 php-app
```

**Mount the source folder (no rebuild):**

```bash
docker run -d --name php-app -p 80:80 -v "$(pwd)/src:/var/www/html" php-app
```

Editing `src/index.php` on the host appears in the browser immediately. This mirrors editing `/usr/share/nginx/html/` in the native setup.

### Step 10: Stop and clean

```bash
docker stop php-app
docker rm php-app
docker rmi php-app
```

## 8. Native vs container comparison

| Native | Container |
|---|---|
| `dnf install` on host | `RUN dnf install` in Dockerfile |
| Edit `nginx.conf` and `conf.d/php-app.conf` with vim | Ship one replacement `nginx.conf` |
| Edit `/etc/php-fpm.d/www.conf` | `sed` in Dockerfile |
| Run as `apache` | Run as `nginx` |
| Unix socket `/run/php-fpm/www.sock` | TCP `127.0.0.1:9000` |
| `setsebool` and `restorecon` | Not needed |
| `firewall-cmd` for port 80 | `-p 80:80` on `docker run` |
| `systemctl enable --now` | `supervisord` |
| `chown -R apache:apache` | `chown -R nginx:nginx` in Dockerfile |
| Debug with `journalctl`, `tail` | Debug with `docker logs`, `docker exec` |

Application files and request flow are identical. Only the surroundings change.

## 9. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Container exits at start | A service failed | `docker logs php-app` shows the error |
| `port is already allocated` | Host Nginx still on port 80 | `sudo systemctl stop nginx` |
| Welcome page on port 80 | `nginx.conf` not copied | Verify `COPY nginx.conf` in Dockerfile, rebuild |
| `502 Bad Gateway` | PHP-FPM not reachable | `docker exec php-app ss -ltnp` shows `127.0.0.1:9000` |
| `403 Forbidden` | Wrong owner on files | `docker exec php-app ls -l /var/www/html` |
| PHP shown as plain text | Nginx not forwarding to PHP | `docker exec php-app grep fastcgi_pass /etc/nginx/nginx.conf` |
| Config syntax error | Typo in `nginx.conf` | `docker exec php-app nginx -t` |

Useful commands:

```bash
docker logs -f php-app           # follow logs live
docker exec -it php-app sh       # open a shell inside the container
docker exec php-app nginx -t     # check nginx config syntax
docker exec php-app ss -ltnp     # show listening ports
```

## 11. Command reference

### Docker

| Command | Purpose |
|---|---|
| `docker --version` | Show version |
| `docker ps` | List running containers |
| `docker ps -a` | List all containers |
| `docker build -t name .` | Build image from current directory |
| `docker images` | List images |
| `docker run -d --name n -p h:c img` | Run in background |
| `docker logs name` | Show container output |
| `docker logs -f name` | Follow logs live |
| `docker exec -it name sh` | Open a shell inside the container |
| `docker stop name` | Graceful stop |
| `docker rm name` | Remove a stopped container |
| `docker rm -f name` | Stop and remove in one step |
| `docker rmi name` | Remove an image |

### Inside the container

| Command | Purpose |
|---|---|
| `nginx -t` | Check Nginx syntax |
| `ss -ltnp` | Show listening ports |
| `ls -l /var/www/html` | Check file ownership |
| `cat /etc/nginx/nginx.conf` | Read the config |

| Command | Purpose |
|---|---|
| `sudo ss -ltnp \| grep :80` | Check what owns port 80 |
| `curl -I http://localhost/` | Test response headers |
