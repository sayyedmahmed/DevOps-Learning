# PHP Application Container Deployment

Step by step deployment of the PHP + Nginx + PHP-FPM stack in a single Docker container. No Docker Compose. Based on the native AlmaLinux setup, containerized.

## Overview

Same architecture as the native setup, just inside a container:

```
Browser  ->  Docker (port 80)  ->  Nginx  ->  PHP-FPM (127.0.0.1:9000)  ->  index.php
```

Two services run inside one container. Supervisor starts and monitors both. One port is exposed to the host.

## Prerequisites

- Docker installed on the host. Check with `docker --version`.
- Host Nginx stopped if it uses port 80 (Step 6 covers this).
- Port 80 free on the host.

---

## Step 1: Verify Docker

```bash
docker --version
docker ps
```

- `docker --version` prints the installed version.
- `docker ps` lists running containers. If it fails with permission denied, add your user to the `docker` group:

```bash
sudo usermod -aG docker $USER
```

Log out and back in, then run `docker ps` again.

---

## Step 2: Create the project folder

```bash
mkdir -p ~/php-docker/src
cd ~/php-docker
```

- `mkdir -p` creates the folder and any missing parents.
- `src/` holds the application files.
- The project root holds `Dockerfile`, `nginx.conf`, and `supervisord.conf`.

Final layout:

```
php-docker/
├── Dockerfile
├── nginx.conf
├── supervisord.conf
└── src/
    ├── index.php
    └── style.css
```

---

## Step 3: Create the application files

Inside `src/`:

```bash
cd ~/php-docker/src
vim index.php
```

Paste the `index.php` content from the reference document.

```bash
vim style.css
```

Paste the `style.css` content.

Vim quick reference: `i` to insert, `Esc` to stop inserting, `:wq` to save and quit.

Verify:

```bash
ls -l ~/php-docker/src/
```

You should see `index.php` and `style.css`.

---

## Step 4: Create the Dockerfile

```bash
cd ~/php-docker
vim Dockerfile
```

Paste the Dockerfile content from the reference document.

The file does five things in order:

1. `FROM almalinux:9` selects the base image.
2. `RUN dnf install ...` installs Nginx, PHP, PHP-FPM, and Supervisor.
3. `COPY` brings the app files and configs into the image.
4. `RUN sed` adjusts PHP-FPM to run as `nginx` and listen on `127.0.0.1:9000`, then fixes file ownership.
5. `CMD` starts Supervisor when the container runs.

Save with `:wq`.

---

## Step 5: Create the config files

```bash
vim nginx.conf
```

Paste the `nginx.conf` content. This file replaces `/etc/nginx/nginx.conf` inside the image. It contains the full `server { }` block, so there is no default server and no port conflict.

```bash
vim supervisord.conf
```

Paste the `supervisord.conf` content. This file tells Supervisor to launch Nginx and PHP-FPM, restart them if they fail, and forward their logs to the container output.

Verify all files exist:

```bash
ls -l
```

Expected:

```
Dockerfile
nginx.conf
supervisord.conf
src/
```

---

## Step 6: Free port 80 on the host

If host Nginx is running, it owns port 80 and the container cannot bind to it.

```bash
sudo systemctl stop nginx
sudo systemctl disable nginx
```

- `stop` ends the running service.
- `disable` prevents it from starting on boot.

Confirm port 80 is free:

```bash
sudo ss -ltnp | grep :80
```

Empty output means port 80 is free. If something else is using it (Apache, another container), stop that too.

If you want to keep host Nginx and use a different host port, change the `-p` flag in Step 8 to `-p 8080:80` and visit `http://<vm-ip>:8080/` instead.

---

## Step 7: Build the image

```bash
cd ~/php-docker
docker build -t php-app .
```

- `docker build` reads the `Dockerfile` in the current directory.
- `-t php-app` tags the resulting image as `php-app`.
- `.` is the build context, meaning "everything in this folder is available to the build".

First build takes 1 to 3 minutes depending on network. Subsequent builds reuse cached layers and are fast.

Watch for errors. Common ones:

| Error | Cause |
|---|---|
| `failed to solve: almalinux:9 not found` | Network issue pulling the base image |
| `COPY failed: no source files` | `src/`, `nginx.conf`, or `supervisord.conf` missing from the project folder |
| `dnf install` timeout | Network slow or repository unreachable |

Confirm the image exists:

```bash
docker images | grep php-app
```

---

## Step 8: Run the container

```bash
docker run -d --name php-app -p 80:80 php-app
```

- `-d` runs the container in the background.
- `--name php-app` gives the container a name so you can reference it later.
- `-p 80:80` maps host port 80 to container port 80. Format is `host:container`.
- `php-app` is the image name.

Confirm it is running:

```bash
docker ps
```

You should see a row with `php-app` and status `Up`. If the container exits immediately, check logs with `docker logs php-app`.

Common exit reasons:

| Reason | Meaning |
|---|---|
| `nginx: [emerg]` in logs | Syntax error in `nginx.conf` |
| `php-fpm: error` in logs | PHP-FPM failed to start. Usually a wrong `listen` address |
| Nothing in logs | Supervisor not starting. Check `CMD` in the Dockerfile |

---

## Step 9: Verify

```bash
docker logs php-app
curl -I http://localhost/
```

- `docker logs` shows stdout from both Nginx and PHP-FPM through Supervisor.
- `curl -I` fetches response headers.

Expected from `curl -I`:

```
HTTP/1.1 200 OK
Server: nginx/...
Content-Type: text/html; charset=UTF-8
```

Open `http://<vm-ip>/` in a browser. You should see the purple card. If the welcome page appears instead, `nginx.conf` did not override the default. Re-check Step 5 and rebuild with Step 7.

If you see PHP source as plain text, Nginx is not forwarding to PHP-FPM. Check inside the container:

```bash
docker exec php-app grep fastcgi_pass /etc/nginx/nginx.conf
```

It should print `fastcgi_pass 127.0.0.1:9000;`.

## Step 10: Daily usage

The app files are baked into the image. Two ways to update them.

### Option A: Rebuild after every change

Edit files in `src/`, then:

```bash
docker rm -f php-app
docker build -t php-app .
docker run -d --name php-app -p 80:80 php-app
```

- `docker rm -f` stops and removes the old container in one step.
- `docker build` rebuilds with the new files.
- `docker run` starts a fresh container.

Slow if you edit often. Good for final deployments.

### Option B: Mount the source folder

```bash
docker run -d --name php-app -p 80:80 -v "$(pwd)/src:/var/www/html" php-app
```

- `-v host:container` mounts a host folder inside the container.
- `$(pwd)` expands to the current directory.

Now editing `src/index.php` on the host is reflected immediately in the browser. No rebuild. This mirrors editing files in `/usr/share/nginx/html/` during native daily usage.

## Step 11: Inspect and troubleshoot

Useful commands:

```bash
docker ps                          # running containers
docker ps -a                       # all containers, including stopped
docker logs php-app                # logs from both services
docker logs -f php-app             # follow logs live
docker exec -it php-app sh         # shell inside the container
docker exec php-app nginx -t       # check nginx config syntax
docker exec php-app ss -ltnp       # listening ports inside the container
docker inspect php-app             # full container metadata
```

- `docker exec` runs a command inside a running container.
- `-it` makes it interactive with a terminal.
- `sh` starts a shell. This replaces `ssh` for containers.

Common issues:

| Symptom | Cause | Fix |
|---|---|---|
| Container exits on start | A service failed | `docker logs php-app` for the exact error |
| `port is already allocated` | Host Nginx still bound to port 80 | `sudo systemctl stop nginx` |
| Welcome page shows on port 80 | `nginx.conf` was not copied | Verify Step 5 and rebuild |
| `502 Bad Gateway` | PHP-FPM not running or not listening | `docker exec php-app ss -ltnp` shows listening ports |
| `403 Forbidden` | Wrong owner on `/var/www/html` | `docker exec php-app ls -l /var/www/html` |
| PHP shows as plain text | Nginx not forwarding to PHP-FPM | `docker exec php-app grep fastcgi_pass /etc/nginx/nginx.conf` |

---

## Step 12: Stop and clean up

```bash
docker stop php-app
docker rm php-app
docker rmi php-app
```

- `stop` sends SIGTERM. Supervisor shuts down both services gracefully.
- `rm` removes the container.
- `rmi` removes the image.

To clean up everything unused:

```bash
docker system prune -a
```

This removes all stopped containers and unused images. Use with care on shared systems.

## Full sequence

Copy this block to rebuild from scratch on a new host.

```bash
# 1. Project structure
mkdir -p ~/php-docker/src
cd ~/php-docker

# 2. App files
# create src/index.php and src/style.css

# 3. Config files
# create Dockerfile, nginx.conf, supervisord.conf

# 4. Free port 80
sudo systemctl stop nginx
sudo systemctl disable nginx

# 5. Build
docker build -t php-app .

# 6. Run
docker run -d --name php-app -p 80:80 php-app

# 7. Verify
docker ps
docker logs php-app
curl -I http://localhost/
```

If `docker ps` shows the container up and `curl -I` returns `200 OK`, the deployment is complete.

## Command reference

### Docker

| Command | Purpose |
|---|---|
| `docker --version` | Show installed version |
| `docker ps` | List running containers |
| `docker ps -a` | List all containers |
| `docker build -t name .` | Build an image from the current directory |
| `docker images` | List images |
| `docker run -d --name n -p h:c img` | Run a container in background |
| `docker logs name` | Show container output |
| `docker exec -it name sh` | Open a shell inside the container |
| `docker stop name` | Graceful stop |
| `docker rm name` | Remove a stopped container |
| `docker rm -f name` | Stop and remove in one step |
| `docker rmi name` | Remove an image |

### Inside the container

| Command | Purpose |
|---|---|
| `nginx -t` | Check Nginx syntax |
| `ss -ltnp` | Show listening ports |
| `ls -l /var/www/html` | Check file ownership |
| `cat /etc/nginx/nginx.conf` | Read the config |

### Host network

| Command | Purpose |
|---|---|
| `sudo ss -ltnp \| grep :80` | Check what owns port 80 |
| `curl -I http://localhost/` | Test headers |
| `curl http://localhost/` | Test full body |

## What changed from the native setup

| Native | Container |
|---|---|
| `dnf install` on host | `RUN dnf install` in Dockerfile |
| Edit `/etc/nginx/nginx.conf` with vim | Ship a replacement `nginx.conf` |
| Edit `/etc/php-fpm.d/www.conf` with vim | `sed` inside the Dockerfile |
| `setsebool` for SELinux | Not needed |
| `firewall-cmd` for port 80 | Not needed, port mapping handles it |
| `systemctl enable --now` | `supervisord` |
| `chown -R apache:apache` | `chown -R nginx:nginx` |
| Unix socket `/run/php-fpm/www.sock` | TCP `127.0.0.1:9000` |

The application files and the request flow are unchanged.
