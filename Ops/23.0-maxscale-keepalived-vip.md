# High Availability: MaxScale with Keepalived (VIP)

**Architecture:** Keepalived floats a Virtual IP (VIP) between two MaxScale nodes. The application only ever connects to the VIP. If the primary MaxScale dies, Keepalived instantly moves the VIP to the backup MaxScale.

---

## 1. Architecture Overview

```text
                  ┌─────────────────────────────┐
                  │   App VM (10.10.10.180)     │
                  │   config.php db_host = VIP  │
                  └──────────────┬──────────────┘
                                 │
                   Connects to   │  10.10.10.250:4006 (VIP)
                                 │
                  ┌──────────────▼──────────────┐
                  │       Keepalived VIP        │
                  └──────┬───────────────┬──────┘
                         │               │
            (Active)     │               │     (Standby)
    ┌────────────────────▼───┐       ┌───▼────────────────────┐
    │ MaxScale 1             │       │ MaxScale 2             │
    │ 10.10.10.190           │       │ 10.10.10.191           │
    │ Holds VIP (MASTER)     │       │ No VIP (BACKUP)        │
    └────────────┬───────────┘       └───────────┬────────────┘
                 │                               │
                 └──────────────┬────────────────┘
                                │ Port 3306
                  ┌─────────────▼─────────────┐
                  │    MariaDB Galera Cluster │
                  │ 10.10.10.201 / 202 / 203  │
                  └───────────────────────────┘
```

| Role | Hostname | IP | Software |
|---|---|---|---|
| App | `app-server` | `10.10.10.180` | Apache + PHP |
| MaxScale 1 (Primary) | `maxscale-1` | `10.10.10.190` | MaxScale + Keepalived |
| MaxScale 2 (Backup) | `maxscale-2` | `10.10.10.191` | MaxScale + Keepalived |
| **VIP** | N/A | **`10.10.10.250`** | Managed by Keepalived |
| Galera Nodes | `mariadb-[1-3]` | `10.10.10.20[1-3]` | MariaDB |

## 2. Prerequisites (Both MaxScale Nodes)

1. **Two MaxScale nodes** in the same Layer-2 network (same subnet).
2. **Keepalived** installed.
3. **Network layout:** In this lab, `eth0` is the internet (NAT), and `eth1` is the internal 10.10.10.x network. **Keepalived MUST bind to `eth1`.**

### 2.1 Ensure MaxScale is configured to listen on all interfaces (or the VIP)
In `/etc/maxscale.cnf`, the listener should **not** be hardcoded to a specific IP unless you use the VIP (and use `notify_master` to restart MaxScale). The safest approach for HA is to have MaxScale listen on all interfaces, and use the firewall to restrict access.

**On both MaxScale nodes**, ensure the listener looks like this:
```ini
[Read-Write-Listener]
type=listener
service=Read-Write-Service
protocol=MariaDBClient
address=0.0.0.0
port=4006
```
Restart MaxScale to apply: `sudo systemctl restart maxscale`

---

## 3. Fix `rp_filter` (Crucial for Multi-NIC Setup)

*If you skip this, Keepalived will break SSH on your MaxScale nodes.*

Linux's Reverse Path Filtering drops packets if the return route doesn't match the incoming interface. Because we have two NICs (`eth0` and `eth1`), we must set `rp_filter` to **Loose Mode (2)**.

**Run on both MaxScale nodes:**
```bash
echo 'net.ipv4.conf.all.rp_filter = 2' | sudo tee /etc/sysctl.d/99-rpfilter.conf
echo 'net.ipv4.conf.eth0.rp_filter = 2' | sudo tee -a /etc/sysctl.d/99-rpfilter.conf
echo 'net.ipv4.conf.eth1.rp_filter = 2' | sudo tee -a /etc/sysctl.d/99-rpfilter.conf
sudo sysctl --system
```

**Run on both MaxScale nodes:**

sudo dnf install keepalived -y

## 5. Configure Keepalived

### 5.1 Primary Node (`maxscale-1` — 10.10.10.190)
Create `/etc/keepalived/keepalived.conf`:

```conf
global_defs {
    router_id MAXSCALE_1
    enable_script_security
    script_user root
}

# Health check: is MaxScale listening on port 4006?
vrrp_script chk_maxscale {
    script "/usr/bin/ss -tln | /usr/bin/grep -q ':4006 '"
    interval 2
    weight -30
    fall 3
    rise 2
}

vrrp_instance VI_MAXSCALE {
    state MASTER
    interface eth1                 # MUST match your internal NIC
    virtual_router_id 51           # MUST be identical on both nodes
    priority 150                   # Higher = MASTER
    advert_int 1
    authentication {
        auth_type PASS
        auth_pass ChangeMe123      # MUST be identical on both nodes
    }
    virtual_ipaddress {
        10.10.10.250/24 dev eth1   # VIP and NIC
    }
    track_script {
        chk_maxscale
    }
}
```

### 5.2 Backup Node (`maxscale-2` — 10.10.10.191)
Create `/etc/keepalived/keepalived.conf`:

```conf
global_defs {
    router_id MAXSCALE_2
    enable_script_security
    script_user root
}

vrrp_script chk_maxscale {
    script "/usr/bin/ss -tln | /usr/bin/grep -q ':4006 '"
    interval 2
    weight -30
    fall 3
    rise 2
}

vrrp_instance VI_MAXSCALE {
    state BACKUP
    interface eth1                 # Same as primary
    virtual_router_id 51           # Same as primary
    priority 100                   # Lower = BACKUP
    advert_int 1
    authentication {
        auth_type PASS
        auth_pass ChangeMe123      # Same as primary
    }
    virtual_ipaddress {
        10.10.10.250/24 dev eth1
    }
    track_script {
        chk_maxscale
    }
}
```

### 5.3 Config Rules (Do Not Mess These Up)
| Directive | Node 1 | Node 2 | Must Match? |
|---|---|---|---|
| `router_id` | `MAXSCALE_1` | `MAXSCALE_2` | **No** (labels) |
| `state` | `MASTER` | `BACKUP` | No (hint only) |
| `interface` | `eth1` | `eth1` | **Yes** |
| `virtual_router_id` | `51` | `51` | **Yes** |
| `priority` | `150` | `100` | **No** (must differ) |
| `auth_pass` | `ChangeMe123` | `ChangeMe123` | **Yes** |
| `virtual_ipaddress` | `10.10.10.250` | `10.10.10.250` | **Yes** |

## 6. Firewall Configuration

VRRP uses **IP Protocol 112**, not TCP/UDP. We must allow it between the two nodes.
Also, we must allow the App VM to reach the VIP on port 4006.

**Run on both MaxScale nodes:**
```bash
# 1. Allow VRRP (protocol 112)
sudo firewall-cmd --permanent --add-rich-rule='rule protocol value="112" accept'

# 2. Allow App VM to reach the VIP on 4006
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="10.10.10.180" destination address="10.10.10.250" port port="4006" protocol="tcp" accept'

# 3. Reload
sudo firewall-cmd --reload
```

## 7. Start and Verify

### 7.1 Start Keepalived
**Run on both MaxScale nodes:**
```bash
sudo systemctl enable --now keepalived
sudo systemctl status keepalived --no-pager
```

### 7.2 Verify on the Primary (`10.10.10.190`)
```bash
ip -br a | grep 10.10.10.250
# Expected: eth1  UP  10.10.10.190/24 10.10.10.250/24
```
If the VIP is on `eth0`, your `dev` or `interface` is wrong in the config. Run `systemctl stop keepalived`, fix it, and start again.

### 7.3 Verify on the Backup (`10.10.10.191`)
```bash
ip -br a | grep 10.10.10.250
# Expected: (no output - VIP is not here yet)
```
Check logs: `sudo journalctl -u keepalived -f` (should say `Entering BACKUP STATE`).

## 8. The App VM Configuration

**On the App VM (`10.10.10.180`)**, update the database host to use the VIP:

`sudo vi /var/www/crudapp/config.php`
```php
<?php
return [
    'db_host' => '10.10.10.250',      // The VIP, NOT .190
    'db_port' => 4006,                // MaxScale port
    'db_name' => 'app_data',
    'db_user' => 'appuser',
    'db_pass' => '123',
];
```
Restart PHP: `sudo systemctl restart php-fpm`

**Test from the App VM:**
```bash
mariadb -h 10.10.10.250 -P 4006 -u appuser -p123 app_data -e "SELECT COUNT(*) FROM contacts;"
```
*If it returns `3`, the connection works through the VIP!*

## 9. Test Failover (HA Magic)

1. Keep an Xshell session open to the **VIP**: `ssh root@10.10.10.250`.
2. On the **Primary** (`10.10.10.190`), stop keepalived to simulate a crash:
   ```bash
   sudo systemctl stop keepalived
   ```
3. Watch the **Backup** (`10.10.10.191`) instantly take the VIP:
   ```bash
   ip -br a | grep 10.10.10.250
   # It is now on eth1!
   ```
4. Your Xshell session to `10.10.10.250` might drop for 1-2 seconds, but reconnecting will land you on the **Backup** node.
5. The App VM can still reach the database without a single config change!
6. Bring the Primary back online:
   ```bash
   sudo systemctl start keepalived   # (on 10.10.10.190)
   ```
   *(Because `priority 150` is higher, it will seamlessly steal the VIP back).*

## 10. Troubleshooting (What went wrong in our build)

| Symptom | Cause | Fix |
|---|---|---|
| **SSH to MaxScale dies instantly when starting Keepalived** | The VIP was accidentally put on `eth0` (the internet NIC), breaking routing. | Change `interface eth1` and `dev eth1` in the config. |
| **SSH dies even with the right NIC** | `rp_filter` is dropping packets on multi-NIC hosts. | Set `net.ipv4.conf.all.rp_filter=2` in `/etc/sysctl.d/`. |
| **VIP never appears on Primary** | VRRP blocked by firewall, or `eth1` is down. | Add `firewall-cmd --add-rich-rule='rule protocol value="112" accept'`. |
| **Both nodes claim to be MASTER** | `virtual_router_id` or `auth_pass` mismatch. | Ensure both config files have the exact same `51` and `ChangeMe123`. |
| **VIP flaps (moves back and forth constantly)** | The `chk_maxscale` script is failing because MaxScale isn't running/listening on 4006. | Check `ss -tlnp \| grep 4006`. Fix MaxScale, or temporarily comment out `track_script`. |
| **`X11 forwarding rejected` in Xshell** | Harmless. Server has no GUI desktop. | Ignore it. |
